Fly escape, on the robot

The same fruit-fly looming-escape circuit as the Fly escape demo, but it runs on the Bittle's own ESP32. The robot sees a hand coming, decides and walks back by itself. Flydeck only listens.

On the robotIR sensor → 348-neuron circuit every 35 ms → back away and stand. Nothing leaves the board to make the decision.
→5 lines a second
On the laptopSwitches the module on or off and draws what the robot reports: the sensor, the giant fibres, every decision.

Before you start

The robot needs firmware with the fly_escape module. Stock Petoi firmware does not have it; the demo says so and stops. How to build and flash it: firmware/bittle/fly_escape/README.md.

What happens

  1. Flydeck connects and asks the robot which modules it has (X?).
  2. If the module is off, it is switched on (XE): the robot stands and measures the sensor's resting level. Keep hands away for a second. It now backs away from a fast-approaching hand, so give it a metre behind.
  3. Flydeck asks for telemetry (XEP) and draws it. A red mark is a decision the robot made.
  4. At Stop, telemetry goes off. The module keeps running unless you unticked Leave the module running. The laptop never sends a motion command.

Try it: start the demo, then pull the USB cable or close Flydeck. The robot keeps escaping.
