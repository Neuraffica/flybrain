Flydeck

Pick a robot, pick a fly-brain demo, press Start. Flydeck is a small Mac app that finds your Bittle over Bluetooth, starts any demo in this repo on it, and stops it safely.

Tested on the simulator. The Bluetooth path through the app is built the same way as the helper that ran fly-escape over Bluetooth, but has not been tried on the robot yet.

What it does

One window, three steps. Everything stays on your Mac: the page is served from 127.0.0.1 and nothing is sent anywhere.

1 · Robot

Find the robot

Scan for it over Bluetooth (or pick the USB cable). Check reads its model, firmware and battery, then lets go of it.

2 · Demo

Pick a demo

Every demo in demos/ is a card with its settings. Tick Try in simulator to run it with no robot at all.

3 · Start

Start and Stop

The demo's dashboard opens inside Flydeck with its live output. Stop (or quitting Flydeck) always lays the robot down to rest.

Install

Once. Flydeck.app needs a Mac with Apple Silicon and nothing else: no Python, no uv, no copy of the code.

  1. Download

    Get Flydeck-<version>-macos-arm64.dmg from the latest release, open it and drag Flydeck to Applications.

  2. Open it the first time

    macOS refuses at first: the app is not notarized by Apple. Click Done, open System Settings › Privacy & Security, click Open Anyway next to the line about Flydeck, and confirm. Or run xattr -dr com.apple.quarantine /Applications/Flydeck.app in Terminal. After that it opens like any app.

  3. Or build it yourself

    In a clone of the repository: uv run flydeck build-app writes dist/Flydeck.app and a .dmg; uv run flydeck install-app also puts the app in ~/Applications.

First run

  1. The Flydeck window opens

    Robot on the left, demo cards on the right. Guides and a demo's dashboard open in their own Flydeck windows; web links open in your browser.

  2. Switch the robot on

    Long-press the battery button until the lights come on. Close the Petoi phone app: a robot connected to a phone does not show up in a scan.

  3. Scan, and allow Bluetooth

    Press Scan. The first time, macOS asks "Flydeck" would like to use Bluetooth: click Allow. macOS remembers the answer. Your robot appears as something like BittleC2_BLE (the name can change between days).

  4. Use, then Check

    Press Use next to it. Flydeck checks it straight away: model, firmware and battery voltage. Flydeck remembers this robot next time.

Running a demo

Click a card, choose its settings, press Start. One demo runs at a time; while it runs, the robot panel says connected by and the demo has the link to itself.

Every demo stands the robot up (that moves the legs a little) and lays it down at the end.

The space check. When your settings make the robot walk, Flydeck shows The robot has space to move. Tick it every time you start: clear the floor around and behind the robot first. In the simulator nothing real moves, so it is not asked.

While it runs you see its state (connecting, calibrating, running, or needs attention with the reason), its dashboard, and its output under Output. Open in its own window gives the dashboard a whole window.

Stop asks the demo to stop: it halts any gait and lays the robot down, usually within a few seconds. If a demo does not finish within 20 seconds, Flydeck ends it by force and tells you that the robot may still be standing: switch it off with its battery button or lift it.

Quit Flydeck (the button, closing the window, Cmd-Q, or Quit on the Dock icon) stops a running demo the same way first. Even if Flydeck is force-quit, the demo is still stopped.

Add your own demo

git clone https://github.com/Neuraffica/flybrain.git
cd flybrain
uv sync
uv run flydeck new-demo fly-groom
uv sync
uv run fly-groom --mock --open

This copies the hello-robot template to demos/fly-groom with the names filled in and adds it to the workspace. Then, in Flydeck, press Use my flybrain folder… above the demo cards (or Demos › Use my flybrain folder… in the menu bar) and choose the flybrain folder. Flydeck now shows that folder's demos, yours included, and runs them with that folder's Python and Flydeck's Bluetooth permission. Flydeck remembers the folder; Use the built-in demos switches back. After another uv sync, press Reload list. If the folder has no .venv yet, Flydeck says so: run uv sync in it. The 15-minute path, the rules, and the robot API are in docs/adding-a-demo.md.

From a terminal

uv run flydeck            # the same page: a window on a Mac, the browser elsewhere
uv run flydeck --browser  # in the web browser
uv run flydeck list       # which demos Flydeck sees, and any problems

This is the way on Windows, Linux and Intel Macs. On macOS, started this way, macOS stops any program that touches Bluetooth, because Terminal has no Bluetooth permission. Flydeck says so on its page and explains a killed demo. Use the app for Bluetooth; it can show the demos of your folder.

Troubleshooting

Scan finds no robot
Is the battery on (long-press the button)? Is the Petoi phone app, or another computer, connected to it? Close it and scan again. Move closer; the bars show signal strength.
"Flydeck is not allowed to use Bluetooth"
You clicked Don't Allow once. Open System Settings › Privacy & Security › Bluetooth, switch Flydeck on, then quit and reopen Flydeck.
"Low power ... The robot won't move"
The board runs on USB power but the servos have none: switch the battery on, or charge it.
Fly escape: calibration failed, escapes refused
Daylight blinds the infrared sensor (it reads about 50 to 170 instead of about 3200). Move the robot away from windows, keep hands away for the first 2 seconds, and press Recalibrate in its dashboard.
"Showing the built-in demos. ... is not there any more"
The flybrain folder you chose was moved or deleted. Press Use my flybrain folder… and choose it again.
"... has no Python environment yet" or "cannot run Flydeck"
Open Terminal in that folder and run uv sync, then choose the folder again.
A card says "not installed: run uv sync"
A new demo folder is there but not installed yet. Run uv sync, then Reload list.
A card shows an error
That demo's flydeck.py failed to load or is not valid; the card says why. The other demos still work.
Something else
The app writes a log to ~/Library/Logs/Flydeck.log. Each demo's output is under Output. Runs are saved in runs/: for the built-in demos in ~/Library/Application Support/flybrain/runs, for your folder's demos in that folder.
Can I use a browser instead?
The page is served on your Mac only, at an address like http://127.0.0.1:8760; while Flydeck runs you can open that address in a browser too. From a clone, uv run flydeck --browser opens it there directly.
